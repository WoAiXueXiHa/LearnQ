# LearnQ 项目范围与验证边界

LearnQ 是面向技术文章学习的 Go AI 应用。当前产品流程为 Markdown 与图片导入、资料准备、五题预览确认、保存作答、冻结提交、逐题反馈、固定版本证据回溯和重新练习。学习报告、延迟复习、知识库问答和受控 Agent 工具链保留为其他入口；五题流程不能被描述为自由规划的多 Agent 系统。

## 核心工程链路

- 异步任务：业务、任务和 Outbox 同事务提交，Redis Lua 调度，MySQL 租约和 generation/token 条件更新防止旧结果写入；Reaper/Reconciler 修复过期租约和队列缺口。
- 资料证据：Goldmark 结构化解析原始 Markdown，Embedding 与原始证据分离；Qdrant 负责检索索引，MySQL 保存版本与权威事实。历史引用核对固定索引、内容哈希、字节及行号，文章重建后仍可访问旧引用。
- AI 练习：固定文本与图片描述生成五题，提交后生成逐题反馈；JSON Schema、允许引用 ID 枚举及服务端结果校验约束结构和身份，未经外部核查的冲突保持待核查。

## 已取得的证据

- Go 单元与 race、MySQL/Redis 集成、Fake API 与浏览器测试已执行；本机合成数据已执行冷备份、新卷恢复及业务读取验证。
- 目标 2 核 2 GB 服务器完成容器部署、Fake 五题 API 验收和 API/Worker 重启恢复。
- DeepSeek 文本与视觉、Cloudflare Embedding 完成合成小样本索引、五题生成/反馈和独立图片描述；真实调用发现并修复截断、参考要点结构、纯标题父章节覆盖和引用 ID 问题。

## 尚未完成的验收

真实反馈存在过度追问和措辞确定性问题。结构及引用身份正确，不代表语义判断可靠；跨文章质量评测、外部权威双来源核查、目标机长期稳定性/完整备份恢复及最终用户验收仍待完成。独立合成图片描述成功也不证明真实公网文章图片处理链路全面通过。

默认 Fake 模式、外部调用预算为零。真实测试预算和密钥只保存在私有配置中，预算预留与 token 估价不是供应商账单。API 保持 localhost 监听，未提供公开未鉴权服务。

## 可复现检查

从仓库根目录运行 `make fmt-check vet test race test-tools`、`make acceptance` 和 `make acceptance-practice`。依赖测试需要独立、可丢弃 MySQL/Redis，并按 RUNBOOK 设置环境变量；缺少私有冻结文章或数据库配置产生的 Skip 不代表验收通过。自动测试使用 Fake/Mock，不应产生外部模型费用。

私有文章、开发状态/计划、交付日志、截图、导出包及部署地址不随代码提交。仓库中的原创合成评测样例与公开冻结标签是测试输入，不是模型质量结果。
